Every action the panel can do is defined once, and that one definition becomes the HTTP API route, the MCP tool and the assistant's tool, with the same permission check and the same activity log entry. An AI tool can do exactly what its token allows, and never more than the person behind it.

## The MCP server

The MCP server is off until you turn it on: **Settings → API keys and MCP → MCP server on**. Turning it off later refuses every token and sign-in from AI tools but keeps them, so turning it back on restores access.

The server URL is your panel's address plus `/mcp`, for example `https://panel.example.com/mcp` (Streamable HTTP). The settings page shows it with ready-made snippets:

### Connecting

New in 0.2.5: **Settings → API keys and MCP** has one-click install links for popular AI tools, with the command or config each one needs. **Ask before destructive actions** and read-only for new tokens are on by default; both can be switched off there if you want your agents to act on their own.

- **OAuth** (recommended): add the URL in a client that supports MCP's OAuth sign-in. The client registers itself, opens the panel in your browser, and you choose what it may do: **Read only** (the default) or **Read and change**. New in 0.2: the page always starts on **Read only**, even when the client asks to change things, and an **Allow** without a choice gives read only, so a client gets write access only when you pick it. The page says what the client asked for. Anyone can register a client under any name, so the page is titled with the host your answer goes back to ("Connect an app at `<host>`?") and marks the name the client gave itself as **name not verified**. Allow it only if you just started the connection from an app at that host. If you signed in more than 15 minutes ago, the panel asks you to [confirm it's you](/people/sign-in-and-security#confirm-its-you) before it shows that page. Its access tokens last 24 hours and refresh by themselves; the connection lasts up to 90 days. **Connected tools** lists every client; revoking one ends all of its tokens.
- **Token**: **Create token** under **MCP tokens** makes a token for clients that take a bearer token. Pick its projects, actions and expiry; it is read-only unless you turn that off. Send it as `Authorization: Bearer <token>`.

MCP tokens start with `seylo_mcp_`. A regular API key does not work on the MCP server.

### Tools

Tools are the panel's actions with dots replaced by underscores: `services_list`, `logs_search`, `deployments_deploy`. A client sees only the tools its token can use, and a read-only token sees only the ones that read. Account security actions (passwords, 2FA, passkeys, API keys) are never available to AI tools. New in 0.2: neither are [host shells](/guides/host-shell) (turning them on or off, or opening one), or adding and changing a [GitLab, Gitea or Bitbucket connection](/guides/git-providers). A token limited to some projects or actions sees only the approvals and activity entries its scope covers; see [How a key is limited](/people/api-keys#how-a-key-is-limited).

Tool results leave secrets out the same way the assistant's do: environment values, database passwords, tokens and file contents read through `files_read` come back as `[redacted]`, so a read-only token never hands them to the model's host.

New in 0.2.15: since a tool cannot read a service's environment values, it changes one variable with `env_setVariable` (`env_setSharedVariable` for a project's shared variables), which keeps every other line as it is, instead of `env_set`, which replaces the whole file. The editor's hints, such as a service's address written out, come back with a fix that names the key and the reference, never the value. See [Set one variable through the API](/guides/environment-variables#set-one-variable-through-the-api).

## Approvals

An action that deletes something or cannot be undone (deleting a service, restoring a backup over current data, removing a domain, resetting a database password, changing a database's version, and similar) never runs straight from an AI tool, even with a read-and-change token. It waits in **Approvals** with the exact input and the tool's reason. A person who could run it themselves clicks **Approve and run**, and it runs with that person's permissions; or **Deny**, with an optional note for the tool. Requests expire after 24 hours. The **Approval requested** alert can notify you. Approving needs a browser session; an API key can deny a request but never approve one.

The tool gets an approval id back and can check later whether it ran (`approvals_get`).

New in 0.2.15: a backup download link (`backups_downloadUrl`) waits for approval too, since the file leaves the panel, though it deletes nothing. With **Ask before destructive actions** off, it runs right away like the rest. See [Download a backup](/guides/backups#download-a-backup).

New in 0.2.16: some calls of a tool wait for approval and others of the same tool do not. `databases_setExposure` waits when it would let clients connect to an exposed database without TLS (see [Connections without TLS](/guides/databases#connections-without-tls)): turning **Allow connections without TLS** on, also by exposing the database again with it, and, while it is on, emptying the allowed IPs or adding addresses the stored list did not cover, such as `0.0.0.0/0`, `::/0`, two ranges that add up to every address, or the tool's own IP in place of yours. Its other calls run right away: ports, the TLS host name, a narrower allow list, turning it off and turning exposure off. A person's own calls, in the panel or with an `api` key, never wait. With **Ask before destructive actions** off, MCP tokens run these calls right away like the rest; the assistant asks before every change anyway.

New in 0.2.2: only MCP tools and the assistant ask for approvals, so **Approvals** shows in the sidebar and the command palette only once the MCP server or the assistant is on. It also shows while a request waits for you, and when you open the page from a link.

## The AI assistant

The panel also has a built-in assistant that uses the same tools, on your own Anthropic API key: **Settings → AI assistant**.

| Setting | What it does |
| --- | --- |
| **Assistant on** | Shows the assistant in the panel |
| **Members can use it** | Otherwise only owners and admins see it |
| **Anthropic API key** | Stored encrypted and checked with a small request before it is saved |
| **Models** | **Automatic** routes Haiku for quick lookups, Sonnet by default and Opus for hard multi-step work; or **Always the same model** for predictable cost |
| **Let automatic routing use Opus** | Off keeps the bill predictable |
| **Monthly budget** | In US dollars; the assistant stops answering for the rest of the month once it is spent |

**Usage** shows the spend so far, the projected bill for the month, and usage per day, model and person.

The assistant acts with the permissions of the person talking to it. It reads on its own, but every change it wants to make, not only deletions, waits in **Approvals** until a person approves it. Secrets are left out of what it sees.

New in 0.2.5: **Settings → AI assistant** walks through getting an Anthropic API key, with links to the right pages.

### Chatting with it

New in 0.2.5: once the assistant is on (and has a key), a chat bubble shows at the bottom right of every page, and the sidebar has an **Assistant** page (**Assistant page** in Settings → AI assistant, on by default; anyone can also hide it from their own sidebar in **Settings → Preferences**).

- Each person has their own chats, with history: start a **New chat**, rename, delete or search them. The bubble and the page show the same chats, and a new chat offers questions about the page you opened it on.
- What the assistant does shows as an action card: what it ran, on what, and the result.
- A change that needs a person shows as an approval card with **Approve** and **Reject**. It is the same request as on **Approvals**, so deciding in either place decides both, and the reply continues once it is decided. **Approvals** now shows where each request came from: **Assistant** and the chat, or **MCP** and the token.
- **Auto** (in the chat's header) runs the assistant's changes without asking, with your permissions, deletions included. It is one setting per person, kept across chats and devices, and off until you turn it on. The composer says when it is on.

## The activity log

Everything an AI tool does, and every refused attempt, is in **Activity** with the client's name and the person it acts for. Passwords, tokens and other secrets are replaced with `[redacted]` before anything is stored.
