---
title: Telemetry
description: The anonymous usage report a panel sends, everything in it, and how to turn it off.
---

A panel sends one small, anonymous report a day so we know roughly how many panels run which version. Nodes never send anything.

## On or off

Changed in 0.2.4: it is **on by default for a new panel**. The setup page shows **Send anonymous usage reports**, switched on, next to the owner account, so you see it and can turn it off before anything is sent: the first report goes a day after setup. The choice is kept with the owner, and **Settings → Telemetry** changes it later.

- **Panels set up before 0.2.4** keep what they had: off, unless an owner or admin turned it on. An update never turns it on.
- **`--no-telemetry`** on the installer starts the setup page with the switch off (you can still turn it on there). `SEYLO_TELEMETRY=off` or `DO_NOT_TRACK=1` in the installer's environment do the same, for example `curl -fsSL https://install.seylo.dev | sudo DO_NOT_TRACK=1 sh`.
- **`SEYLO_TELEMETRY=off`** (or `0`, `false`, `no`) or **`DO_NOT_TRACK=1`** on the panel's own container turns reports off whatever the setting says. The setup page and **Settings → Telemetry** then show the switch off and locked, naming the variable, and `settings.updateTelemetry` refuses to turn it on (`409`, reason `telemetryOffByEnv`). This is for panels you run yourself; on a panel the installer set up, use the setting.

## What is sent

```json
{
  "installId": "Xb3kQ2...",
  "version": "0.1.0",
  "nodes": 3,
  "services": 12
}
```

| Field | What it is |
| --- | --- |
| `installId` | A random id the panel generates once. It is not derived from anything on the panel, and the receiving end hashes it before storing it. |
| `version` | The panel's version |
| `nodes` | How many nodes the panel manages |
| `services` | How many services exist in total |

That is all: no hostnames, domains, IP addresses, emails, project or service names, or anything about what you deploy. **What is sent** on the Telemetry page shows the exact report the next send would carry, whether telemetry is on or not, along with the install id, where it goes, how often, and when the last and next reports are.

## How often and where

With telemetry on, the panel sends the report every 24 hours, at a time spread over the day so panels don't all report at once. It goes to `https://api.seylo.dev/telemetry`. The receiving end keeps one row per install per day and drops any other field, so even the exact send times are not stored. It also caps how many new installs it counts per day, per address and in total, so made-up install ids can't fill its database; a panel turned away by that cap is counted with its next report.

Turning telemetry off stops the reports at once, and with it off at setup none is ever sent.

## Node locations

New in 0.2.5: when a node joins with an empty **Location**, the panel asks Seylo's site API once for the city and country of the node's public IP address (Geolocation by DB-IP), and fills in the field marked **Detected** until someone saves it. Only the IP address is sent; private and reserved addresses never are. The site API does not log or keep the address.

It is not done after the installer's `--no-telemetry`, nor while `SEYLO_TELEMETRY=off` or `DO_NOT_TRACK=1` is set on the panel's container. A location you typed or saved is never replaced.
