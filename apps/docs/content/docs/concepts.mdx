## Panel

The web app, the HTTP API and the MCP server, in one container. It keeps its state in SQLite on the node it runs on and runs as a service in a protected project called **Panel**, managed by that node's agent like any other service.

The panel decides what should run where. Nodes do not need it to keep working: they keep running, restarting and routing their services while it is down.

The web app hears about changes over one live connection per browser tab, so lists, deploys and statuses update without a reload. Changed in 0.2.16: the panel sends that connection a heartbeat every 15 seconds. A tab that hears nothing for about 40 seconds, or gets no answer within 10 seconds of being shown again or of the network coming back, connects again and reloads what it shows. Before, a connection that died silently, after a laptop slept, changed networks, or a proxy dropped it, left the tab without updates until a reload, with no error. The panel also closes a connection that went silent for 2.5 minutes, or fell more than 16 MiB behind, so its tab reconnects instead of missing updates unseen.

## Node

A Linux server with Docker and the Seylo agent. The agent is one static binary, `seylo`, that is also the node's command line (`seylo status`). It dials out to the panel over one WebSocket, signs in with its own Ed25519 key, and then:

- receives the full desired state of the node and applies it: containers, routes, networks, crash policy, cron jobs,
- runs one-off jobs the panel asks for: builds, commands, file access, backups, cleanup,
- streams logs, metrics and events back, and keeps important events (crashes, deploy results, cron runs, backups) on disk until the panel has them.

A node can be allowed to build images (**Can build**) or only run images built elsewhere. Whoever creates a node's join command chooses, with **Build images on this node** in **Add node**, ticked by default since 0.2.1; an owner or admin can change it later on **Nodes**. A build node gets the source and build secrets of everything it builds, so untick it for servers you do not fully trust (see [Where builds run](/guides/github-and-git#where-builds-run)).

## Project

A group of services with its own private Docker network. Services in a project reach each other by service name (`db:5432`); services in other projects can't reach them at all.

New in 0.2.1: to keep a project you rarely open, such as the protected **Panel** project, out of the way, pick **Hide project** in its **...** menu in the sidebar or on its card on the home page. It changes only your own view, and nothing is hidden by default. **Hidden (N)** at the end of the sidebar and **Show hidden** on the home page list hidden projects without unhiding them, and the command palette, links and the project's own page still open them. **Unhide project** in the same menu brings a project back.

New in 0.2.2: the **+** next to a project's **...** menu in the sidebar opens the new service menu with that project chosen. It shows on hover or keyboard focus, always on touch screens, and not on the **Panel** project. The logo and the panel's name at the top of the sidebar go to the dashboard.

New in 0.2.6: drag projects in the sidebar or on the dashboard, and services in the sidebar, on the dashboard and on the project page, into your own order. It is kept on the server for you, so every device shows it and nobody else's changes. Fixed in 0.2.15: a dropped project or service stays where you drop it, with the mouse or the keyboard, also while a deploy refreshes the list; before, the list showed the old order for a moment and the item slid back from a whole drag away. A save that fails still puts the old order back and says so. Also fixed: with many projects, only the sidebar's projects list scrolls, and the search box, the links, the nodes card and your account row keep their size. Changed in 0.2.16: a project folds on its own in the sidebar and on the home page. Its chevron in the sidebar folds it there only, and the home page's chevrons, **Expand all** and **Collapse all** change only the home page. Both are kept on the server for you, so they follow you to other browsers, and the update kept what you had folded in both. While the projects load, the placeholders take the shape they last had in this browser, so a reload no longer shows every project open first. In the API, `projects.setCollapsed` takes `where` (`sidebar`, the default, or `dashboard`), and projects carry `dashboardCollapsed` next to `collapsed`. A project's **Settings** tab has an **Image** card: upload a PNG, JPEG or WebP (its middle square is used, scaled to 256 px in the browser) to show it instead of the project's initial in the sidebar, on the dashboard and in the project's header, for everyone who sees the project. **Remove image** brings the initial back. Changing it takes the right to edit the project (`projects.update`).

<Callout title="Private networks are per node">
A project's network exists on each node separately; no network spans nodes. If a service points at an internal address of a service on another node, the environment editor underlines it in red. Expose the target (databases get TLS) and use its exposed address, or move the two services onto one node.
</Callout>

## Service

Something that runs in a project:

| Kind | What it is |
| --- | --- |
| App | Your code or image: from GitHub, any Git host, a Docker image, a Dockerfile typed in the panel or an uploaded archive |
| Database | PostgreSQL, MySQL, MariaDB, MongoDB, Redis, and (new in 0.2) Valkey, KeyDB, Dragonfly or ClickHouse, with a web UI, a shell, TLS exposure and backups |
| Compose stack | A compose file; each of its services becomes a member with its own logs, domains and deploys |
| Cron service | A command that runs on a schedule in a one-off container |
| Box | VS Code in the browser (code-server) on the project network |

Apps and compose members get logs that survive deploys, metrics with history, a console, a shell, a **Files** browser for their volumes, notes, alert rules and a crash policy. Cron services get the same except the console and the shell. Databases get logs, metrics, **Files**, a database shell, backups, notes, alert rules, resource limits, the crash policy and **Move to another node**; Boxes get logs, metrics, **Files** and notes. Changed in 0.2.16: databases have an **Advanced** tab for the last three (see [Advanced tab](/guides/databases#advanced-tab)).

## Right-click menus

New in 0.2.16. Right-clicking a service or a project gives the same menu as its **...** button: in the sidebar, on the home page's **Cards**, **List** and **Table** views and on the project page. So do a node's row on **Nodes**, which also gets a **...**, the rows of the **Deployments**, **Domains**, **Backups**, **Cron jobs**, **Alerts** and database **Users** tabs, the assistant's chats, and every table row with a **...** menu. On a touch screen a long-press opens it, and from the keyboard Shift+F10 or the context menu key opens it for the focused row.

| Menu of | Items |
| --- | --- |
| A service | **Open**, **Open in new tab**, **Deploy**, **Cancel deploy** while a deploy runs or else **Restart**, **Stop** and **Start** (during a move to another node only **Cancel move**, while the move can still be cancelled; a Box: **Stop** and **Open editor**), **Logs**, **Console**, **Clone**, **Move to project**, **Move to another node**, **Copy address** (or the internal address), **Copy ID** and **Delete** |
| A project | **Open**, **Open in new tab**, **New service**, **Rename**, **Collapse** or **Expand** (in the view the menu is in), **Hide project** or **Unhide project**, **Settings**, **Copy ID** and **Delete**, which waits until the project has no services |
| A node | **Open**, **Health**, **Run health checks**, **Shell**, **Cleanup**, **Settings**, **Update now** when an update is there, and its addresses and ID to copy |

Items follow the rules of the buttons they stand for: they are hidden or disabled as there, a refusal from the panel shows as a toast, **Stop** and **Delete** ask first, as the header and the **Settings** tab do, and the protected **Panel** project and the panel's own service offer less. The browser's own menu stays on text fields, the code editors, terminals, logs, code and copy fields, on selected text, and anywhere with Shift+right-click; on a touch screen a long-press there keeps the browser's text selection. Nothing opens on a drag handle or while you drag.

## Deployment

One version of a service: its source (a commit, an image or an upload), where it was built, its build and deploy log, its health check result and who or what started it (manual, push, API, rollback, preview, template, webhook or move). Each deployment also keeps the environment it started with, so saving a variable never changes a running version by surprise.

The images of the last five successful deployments are kept, so rolling back is a switch, not a rebuild.

## Domain

A hostname (and optionally a path) routed to a service by Traefik on the service's node, with a Let's Encrypt certificate or one you upload. A service can have many domains; one is **primary** and is what `${{service.URL}}` and IP:port redirects point to. Each domain can add basic auth, an IP allowlist, a rate limit and redirects.

## People

Everyone signs in to the panel with a role:

| Role | Can do |
| --- | --- |
| Owner | Everything, including managing other owners |
| Admin | Everything except changing owners |
| Member | Only the projects and services shared with them, with the actions picked when sharing |

See [Users and access](/people/users-and-access).
