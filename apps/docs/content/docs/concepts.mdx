## Panel

The web app, the HTTP API and the MCP server, in one container. It keeps its state in SQLite on the node it runs on and runs as a service in a protected project called **Panel**, managed by that node's agent like any other service.

The panel decides what should run where. Nodes do not need it to keep working: they keep running, restarting and routing their services while it is down.

## Node

A Linux server with Docker and the Seylo agent. The agent is one static binary, `seylo`, that is also the node's command line (`seylo status`). It dials out to the panel over one WebSocket, signs in with its own Ed25519 key, and then:

- receives the full desired state of the node and applies it: containers, routes, networks, crash policy, cron jobs,
- runs one-off jobs the panel asks for: builds, commands, file access, backups, cleanup,
- streams logs, metrics and events back, and keeps important events (crashes, deploy results, cron runs, backups) on disk until the panel has them.

A node can be allowed to build images (**Can build**) or only run images built elsewhere. Nodes that join, unlike the panel's own node, only run images until an owner or admin allows builds, because a build node gets the source and build secrets of everything it builds (see [Where builds run](/guides/github-and-git#where-builds-run)).

## Project

A group of services with its own private Docker network. Services in a project reach each other by service name (`db:5432`); services in other projects can't reach them at all.

<Callout title="Private networks are per node">
A project's network exists on each node separately; no network spans nodes. If a service points at an internal address of a service on another node, the environment editor underlines it in red. Expose the target (databases get TLS) and use its exposed address, or move the two services onto one node.
</Callout>

To keep a project you rarely open, such as **Panel**, out of the way, pick **Hide project** in its **...** menu in the sidebar or on its dashboard card. It leaves only your own sidebar and dashboard: **Hidden** at the end of the sidebar and **Show hidden** on the dashboard show it again, the command palette and links still open it, and **Unhide project** in the same menu brings it back.

## Service

Something that runs in a project:

| Kind | What it is |
| --- | --- |
| App | Your code or image: from GitHub, any Git host, a Docker image, a Dockerfile typed in the panel or an uploaded archive |
| Database | PostgreSQL, MySQL, MariaDB, MongoDB, Redis, and (new in 0.2) Valkey, KeyDB, Dragonfly or ClickHouse, with a web UI, a shell, TLS exposure and backups |
| Compose stack | A compose file; each of its services becomes a member with its own logs, domains and deploys |
| Cron service | A command that runs on a schedule in a one-off container |
| Box | VS Code in the browser (code-server) on the project network |

Apps and compose members get logs that survive deploys, metrics with history, a console, a shell, a **Files** browser for their volumes, notes, alert rules and a crash policy. Cron services get the same except the console and the shell. Databases get logs, metrics, **Files**, a database shell, backups, notes and alert rules; Boxes get logs, metrics, **Files** and notes.

## Deployment

One version of a service: its source (a commit, an image or an upload), where it was built, its build and deploy log, its health check result and who or what started it (manual, push, API, rollback, preview, template, webhook or move). Each deployment also keeps the environment it started with, so saving a variable never changes a running version by surprise.

The images of the last five successful deployments are kept, so rolling back is a switch, not a rebuild.

## Domain

A hostname (and optionally a path) routed to a service by Traefik on the service's node, with a Let's Encrypt certificate or one you upload. A service can have many domains; one is **primary** and is what `${{service.URL}}` and IP:port redirects point to. Each domain can add basic auth, an IP allowlist, a rate limit and redirects.

## People

Everyone signs in to the panel with a role:

| Role | Can do |
| --- | --- |
| Owner | Everything, including managing other owners |
| Admin | Everything except changing owners |
| Member | Only the projects and services shared with them, with the actions picked when sharing |

See [Users and access](/people/users-and-access).
