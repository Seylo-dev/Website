Available from Seylo 0.2. The `[skip ci]` markers are new in 0.2 too, for every source that deploys on push.
</Callout>

In a monorepo, every push deploys every service that follows the branch. Watch paths stop that: a service deploys on push only when the push changes at least one file its patterns count.

They apply to every way a push reaches a service: GitHub, GitLab, Gitea/Forgejo and Bitbucket webhooks, the panel's branch polling, and the [deploy trigger URL](/guides/github-and-git#deploy-trigger-url). Deploys you start yourself (**Deploy**, **Redeploy this commit**, the API) always run.

## Set them

On the service's **Source** tab, **Watch paths** takes one pattern per line. **Save watch paths** applies them to the next push. An empty list turns them off: every push deploys.

The card shows for services that deploy from GitHub, GitLab, Gitea, Bitbucket or a Git URL.

## Patterns

Patterns are matched against each changed file's path from the repository root. The service's **Root directory** does not change that: write `apps/web/**`, not `**` inside `apps/web`.

| Pattern | Matches |
| --- | --- |
| `*` | Any characters in one folder, never `/`. `*.md` is a Markdown file in the root only. |
| `**` | Any characters, across folders. `apps/web/**` is everything under `apps/web`. |
| `**/` | Any number of folders, also none. `**/*.md` is a Markdown file anywhere, the root included. |
| `?` | One character, not `/`. `go.?od` matches `go.mod`. |
| a trailing `/` | Everything below the folder: `docs/` is the same as `docs/**`. |
| a leading `!` | Excludes what the rest of the pattern matches |

A leading `./` or `/` is dropped. A service may have up to 50 patterns of up to 300 characters each.

### Dot segments are refused

Changed in 0.2.15. Patterns start at the repository root, and git names changed files without `.` or `..` segments, so a pattern with one (`apps/docs/..`, `../shared/**`, `src/./lib`) never matches a file. Such a pattern used to be saved, and then every push after it was "Skipped by watch paths". Saving now refuses it with a hint:

```text
apps/docs/.. never matches a file: paths start at the repository root. To watch a folder, write apps/docs/**
```

The **Watch paths** card shows the same message under the patterns as you type and keeps **Save watch paths** off until it is fixed. `services.setWatchPaths` in the API and MCP refuses it, with the entry's field (`watchPaths.<n>`), and an [import](/guides/export-and-import) leaves such watch paths out with a warning. The patterns themselves work as before. Patterns saved before 0.2.15 are not changed: if the **Source** tab shows the message for one, replace it with the pattern it suggests, or its pushes keep being skipped.

### How a push is decided

For each changed file, the last pattern that matches it decides: a plain pattern counts the file, a `!` pattern drops it. A file no pattern matches does not count, except when every pattern starts with `!`: then every file they do not exclude counts.

The push deploys when at least one changed file counts. Otherwise it is skipped; for a webhook delivery or a trigger call, **Recent deliveries** on the Source tab says why. A deploy that ran writes the deciding line into its log, for example `Watch paths: apps/web/src/index.ts matches apps/web/**.`

When the panel cannot know every changed file, the push deploys: watch paths never skip a push on a guess. The files come from the push payload; when the payload lists none or cut the list short (very large pushes), the panel asks the provider which files changed between the old and the new head. If that fails too, or the provider's answer is capped as well, the push deploys. Matching has a work limit per push, set well above real pushes: 20,000 changed files with paths of about 200 characters, against 50 typical patterns, are decided in full. Only patterns and paths built to be slow reach the limit; such a push deploys, with "Watch paths: too many changed files to match (stopped after ... of ...), so this push deploys." in its log. A changed path longer than 4,096 characters is not matched at all: the list counts as incomplete, so the push deploys.

## Examples

Deploy the web app of a monorepo, and the UI package it uses:

```text
apps/web/**
packages/ui/**
```

| Changed file | Result |
| --- | --- |
| `apps/web/src/index.ts` | Counts (`apps/web/**`) |
| `packages/ui/button.tsx` | Counts (`packages/ui/**`) |
| `apps/api/main.go` | Does not count |
| `README.md` | Does not count |

Deploy on everything except documentation (only `!` patterns, so everything else counts):

```text
!**/*.md
!docs/
```

| Changed file | Result |
| --- | --- |
| `src/app.ts` | Counts (not excluded) |
| `README.md` | Excluded by `!**/*.md` |
| `docs/intro.txt` | Excluded by `!docs/**` |

The last match wins, so a later pattern can take a file back:

```text
src/**
!src/**/*.md
src/docs/changelog.md
```

| Changed file | Result |
| --- | --- |
| `src/app.ts` | Counts (`src/**`) |
| `src/docs/setup.md` | Excluded by `!src/**/*.md` |
| `src/docs/changelog.md` | Counts (the last pattern matches it) |

A Go service that only cares about its code and build files:

```text
Dockerfile
go.?od
src/**/*.go
```

`go.sum` and `cmd/tool.go` do not count; `go.mod`, `src/main.go` and `src/a/b/c.go` do.

## Try it

Under the patterns, **Try it** takes a list of changed files, one per line, and shows what a push with them would do (**This push would deploy** or **This push would be skipped**) and, for each file, the pattern that decided. It runs the same matcher as the panel, so the answer is the one a real push gets.

## Skip a push from the commit message

Independent of watch paths, a push whose head commit message contains `[skip ci]`, `[ci skip]`, `[skip cd]` or `[cd skip]` (any case) never deploys. This holds for every source with deploy on push, also without watch paths.

## The deploy trigger URL

A `POST` to a service's deploy trigger URL goes through the watch paths when its body says what changed. Send either a push payload in the shape GitHub, GitLab or Gitea use (`commits[].added`, `modified`, `removed`, `before`, `after`), for example by pointing a webhook of another git host at the URL, or a list of files:

```bash
curl -X POST "https://panel.example.com/api/hooks/deploy/<token>" \
  -H "Content-Type: application/json" \
  -d '{"changedFiles": ["apps/web/src/index.ts", "README.md"]}'
```

With only `?commit=<sha>` and no body, the panel asks the service's git source which files changed between the live deployment's commit and that one, when the source can say. A call with neither deploys.

A `changedFiles` list keeps at most 20,000 entries; a longer one counts as cut short, so the call deploys.

A skipped call answers `200` with `"deploymentId": null` and the reason in `skipped`.

## Good to know

- Watch paths do not apply to pull and merge request previews: every push to an open request deploys its preview.
- Compose stacks take watch paths through the API (`services.setWatchPaths`, see the [API reference](/api-reference)); their **Source** tab has no editor yet.
- Changing watch paths is in the activity log and needs permission to change the service.
