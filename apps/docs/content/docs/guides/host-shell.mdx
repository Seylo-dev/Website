title: Host shell
description: A root shell on the node itself, in the browser. Off until the owner turns it on per node, owners and admins only, and every session is in the activity log.
---

<Callout title="New in 0.2">
Available from Seylo 0.2, and needs a 0.2 agent on the node.
</Callout>

The host shell is a login shell on the server itself, not in a container, opened from the panel in the browser. It runs as the agent's user, which is root on a normal install, so whoever uses it can do anything on that machine. It goes through the node's existing connection to the panel: nothing is opened on the node, and you need no SSH access.

For a shell inside a service's container, use the service's **Shell** tab instead (see [Logs, console, shell and files](/features/logs-and-terminals#shell)).

## Turn it on for a node

Host shells are off on every node until the owner turns them on, one node at a time:

<Steps>
<Step>

### Open the node's Shell view

On **Nodes**, open the node and pick **Shell**. It says **Host shells are off for this node**.

</Step>
<Step>

### Allow host shells

Click **Allow host shells**, then **Allow host shells** again in the **Allow root shells on ...?** dialog. Only someone with the owner role can do this, from a browser that signed in within the last 15 minutes; otherwise the panel asks you to [confirm it's you](/people/sign-in-and-security#confirm-its-you) first. API keys and AI tools cannot turn host shells on.

</Step>
</Steps>

Turning them on raises a **Security change** alert. **Turn off** in the same view works for owners and admins (and API keys that may manage nodes), and closes every open host shell on the node at once.

### Refuse them on the node itself

To make sure a node never gives out a host shell, whatever the panel says, add this to `/var/lib/seylo/config.yml` on the node and restart the agent:

```yaml title="/var/lib/seylo/config.yml"
no_host_shell: true
```

```bash
systemctl restart seylo
```

Only someone with root on the node can set it, and the panel cannot change it. Joining the node again with `seylo join --force` keeps it. The agent checks both this and the panel's setting itself for every shell, so a panel that skipped its own check still gets nothing.

## Open a shell

In the node's **Shell** view, click **Open root shell**. The terminal says where it is connected, as which user and in which folder, and that it closes after 15 minutes idle. **Close shell** ends it.

To open one you need:

- the owner or admin role: opening a host shell (**Open a root shell on a node**) is a panel-wide action, which is never shared with members,
- a browser session that signed in or confirmed it's you within the last 15 minutes. API keys and MCP tokens are refused, even ones that may do everything,
- host shells turned on for the node, the node online, and a 0.2 agent on it.

New in 0.2.1: **Install on the server** in **Settings → Tailscale** opens the panel node's **Shell** view with the Tailscale install command typed in. Check it, then press Enter: the panel never presses Enter for you, and it types only commands from a short fixed list, nothing a link can make up. When host shells are off for the node, or you can't open one, the view shows the command to run over SSH instead. See [The panel on Tailscale](/self-hosting/tailscale).

## Limits

- At most 2 host shells per node are open at once.
- A shell closes after 15 minutes without input or output.
- Every 30 seconds, the panel checks that your browser session still exists, that you are still an active owner or admin, and that host shells are still on for the node. If any of that changed, the shell closes.
- A panel restart ends every open shell. So does an agent restart or update: the shell runs inside the agent's own service.
- Closing a shell hangs up its processes, like an SSH logout. Programs started in their own session (`setsid`, `nohup` and most daemons) keep running.

## What is recorded

The activity log has an entry for each of these, with who, when and from where:

| Entry | What it records |
| --- | --- |
| **Allow or forbid host shells on a node** | The node and the new setting |
| **Open a root shell on a node** | The node |
| **Close a root shell on a node** | The node, when it was opened, how long it was open, and why it closed (for example the shell exited, it sat idle, or host shells were turned off) |

A shell the panel's restart ended gets its close entry at the next start, with the reason **the panel restarted** and the duration up to the last 30-second check. A shell the node refused (`no_host_shell`, its own limit) is recorded as closed with the node's reason.

Opening a host shell also raises a **Security change** alert, so send that alert to a channel you read (see [Alerts and notifications](/features/notifications)). The node's agent log (`seylo logs` on the node) also names who opened each shell.

<Callout type="warn" title="No session recording">
The activity log says who opened a shell, on which node, when and for how long. It does not record what was typed or printed. Treat a host shell like SSH access as root.
</Callout>
