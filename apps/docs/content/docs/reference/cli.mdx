One binary, `seylo`, is the node agent (`seylo agent`, started by systemd), the node's command line and the command line for your laptop. Release builds exist for Linux, macOS and Windows; see [Command line](/guides/command-line) for installing it on a laptop.

## Global flags

Every command takes these:

```text
      --log-format string   log format: text or json (default "text")
      --log-level string    log level: debug, info, warn or error (default "info")
      --profile string      saved panel login to use (laptop commands)
```

`seylo <command> --help` prints the same help as below.

## Node commands

Run these as root on a node. They talk to the local agent through its socket in `/var/lib/seylo/run/` and to systemd. Off Linux they answer that they run on a Linux server.

### `seylo agent`

Run the node agent (started by systemd)

```text
Usage:
  seylo agent [flags]

Flags:
      --can-build            only sets can_build in config.yml (--can-build=false clears it; a re-join without the flag keeps it). Whether the panel sends builds is chosen when the join command is made, and later under Nodes
      --force                join again although this node already joined a panel (keeps the rest of config.yml)
  -h, --help                 help for agent
      --insecure             accept a plain http:// panel URL on another host (the agent protocol is then unencrypted)
      --join string          join this panel before starting (with --token)
      --name string          node name shown in the panel (default: the hostname; a re-join keeps the one in config.yml)
      --pin string           panel certificate pin (sha256:<hex>) for a panel without a public certificate
      --token string         single-use join token from the panel's Add node dialog
      --trust-on-first-use   pin whatever certificate the panel presents on the first connection
```

##### `seylo panel ip-access on`

Turns "Serve on IP address" and the agents' port back on, for when the panel
domain or the tailnet stopped working while they were off. Restarts the panel
(twice, a few seconds each). Run it as root on the server that runs the panel:

#### `seylo panel rotate-key`

Replaces master.key in the panel's data dir and seals every stored secret again with the new key.
Run it as root on the node that runs the panel, after a copy of the data dir (or of master.key) leaked.
It stops the agent and the panel, runs the rotation from the panel's image, starts the agent again
(which starts the panel) and prints what to do next. Services keep running throughout.

  --new-panel-identity   panel.db leaked (a copy of the data dir, a backup): the panel's identity keys
                         and the agents' TLS key are replaced too, so every node must be joined again;
                         the command prints the nodes and the seylo join command for each.
  --keep-panel-identity  only master.key leaked: the identity keys are sealed again, nodes keep working.

Both delete recovery codes (people make new ones in Settings &gt; Security).

```text
Usage:
  seylo panel rotate-key (--new-panel-identity | --keep-panel-identity) [flags]

Flags:
  -h, --help                  help for rotate-key
      --keep-panel-identity   only master.key leaked: keep the panel's identity, nodes keep working
      --new-panel-identity    panel.db leaked: replace the panel's identity keys and the agents' TLS key too (every node joins again)
      --timeout duration      how long to wait for the panel to answer afterwards (default 3m0s)
```

#### `seylo panel tailscale`

See or stop the panel on this server's tailnet

```text
Usage:
  seylo panel tailscale [command]

Available Commands:
  off         Remove the panel from this server's tailnet and keep it off
  on          Undo `panel tailscale off`
  status      Show this server's Tailscale and the panel's Serve entry, without the panel

Flags:
  -h, --help   help for tailscale
```

##### `seylo panel tailscale off`

Writes no_tailnet: true to config.yml, restarts the agent and removes the panel's
Tailscale Serve entry, so the agent adds none and refuses Tailscale sign-in and DNS
changes from the panel. Tailscale itself keeps running. `seylo panel tailscale on` undoes it.

```text
Usage:
  seylo panel tailscale off [flags]

Flags:
  -h, --help   help for off
```

##### `seylo panel tailscale on`

Removes no_tailnet from config.yml and restarts the agent. It adds the panel's Serve
entry again if the panel still has "Serve the panel on my tailnet" on.

```text
Usage:
  seylo panel tailscale on [flags]

Flags:
  -h, --help   help for on
```

##### `seylo panel tailscale status`

Reads the server's tailscaled directly, so it works while the agent or the panel is down:
the state, the tailnet, the machine name, the panel's Serve entry, and the sign-in link
when Tailscale waits for one.

```text
Usage:
  seylo panel tailscale status [flags]

Flags:
  -h, --help   help for status
```

### `seylo troubleshoot`

Collects versions, health checks, the agent's state and logs, Docker and the Seylo
containers into a Markdown report with secrets, tokens and email addresses removed,
uploads it and prints a link to share. --dry-run prints the report instead.

```text
Usage:
  seylo troubleshoot [flags]

Flags:
      --dry-run                print the redacted report instead of uploading it
  -h, --help                   help for troubleshoot
      --include-service-logs   add the last lines of every service's logs
      --keep-emails            keep email addresses (removed by default)
      --print                  same as --dry-run
      --redact-ips             also replace public IP addresses
```

### `seylo login`

Signs in to a panel and saves an API key in ~/.config/seylo/config.json.
By default it opens the panel's approval page in your browser: check the code, pick
what the key may do and approve. With --token or --token-stdin it saves an API key
you created under Settings &gt; API keys and MCP instead.

```text
Usage:
  seylo login <panel-url> [flags]

Flags:
  -h, --help             help for login
      --no-browser       print the approval link instead of opening a browser
      --profile string   name for these saved credentials (default "default")
      --token string     API key (default: approve the sign-in in the browser)
      --token-stdin      read the API key from standard input
```

### `seylo logout`

Forget the saved API key

```text
Usage:
```
